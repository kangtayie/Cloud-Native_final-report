# 3단계 배포 가이드: 따라 말하기 (Amazon Transcribe)

리전은 **서울(ap-northeast-2)** 입니다. 원어민 발음을 듣고 따라 말하면, 현지어 음성 인식기가 알아들은 정도를 **일치율(%)과 틀린 단어**로 보여줍니다.

```
브라우저(녹음) → POST /practice → practice-lambda → S3 녹음 버킷 저장 → Transcribe 작업 시작 → jobId 응답
브라우저 → 3초마다 GET /practice/{jobId} → practice-lambda → Transcribe 결과 확인 → 일치율 계산 → 응답
```

## 0. 비용 (서울, 2026-11-16 AWS Price List API 조회)
| 항목 | 단가 | 1회 연습 |
|---|---|---|
| Transcribe 일괄 인식 | $0.0001/초, 요청당 최소 15초 과금 | 약 $0.0015 (1,000회 약 $1.5) |
| S3 녹음 버킷 | 수십 KB × 1일 보관 | 사실상 $0 |
| Lambda, API Gateway | 요청 몇 건 | 사실상 $0 |
- 상시 과금 리소스 없음. 녹음은 1일 후 자동 삭제.

## 1. S3 녹음 버킷 `local-speak-rec-2026`
웹사이트 버킷과 **별개의 비공개 버킷**입니다.
1. S3 → **버킷 만들기**
   | 항목 | 값 |
   |---|---|
   | 버킷 이름 | `local-speak-rec-2026` (이미 있으면 뒤에 숫자를 붙이고 아래 값도 모두 바꿈) |
   | 리전 | 서울 |
   | 모든 퍼블릭 액세스 차단 | **켜둔 그대로** (웹사이트 버킷과 다름) |
   | 버킷 버전 관리 | 비활성화 |
   | 암호화 | SSE-S3 (기본값) |
2. 만든 버킷 → **관리** 탭 → **수명 주기 규칙 생성**
   | 항목 | 값 |
   |---|---|
   | 규칙 이름 | `delete-after-1-day` |
   | 규칙 범위 | **버킷의 모든 객체에 적용** (경고 확인 체크) |
   | 수명 주기 규칙 작업 | **객체의 현재 버전 만료** 체크 |
   | 객체 생성 후 경과 일수 | `1` |
   → **규칙 생성**

## 2. IAM 역할 `role-practice-lambda`
1단계와 같은 방법(AWS 서비스 → Lambda → `AWSLambdaBasicExecutionRole`)으로 만들고, 인라인 정책 `transcribe-s3-minimal`을 붙입니다.
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["transcribe:StartTranscriptionJob", "transcribe:GetTranscriptionJob"],
      "Resource": "*"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject"],
      "Resource": "arn:aws:s3:::local-speak-rec-2026/practice/*"
    }
  ]
}
```
- S3 권한은 **녹음 버킷의 `practice/` 폴더**로만 제한합니다 (웹사이트 버킷이나 다른 버킷은 건드릴 수 없음).
- Transcribe는 녹음을 읽을 때 호출한 람다의 권한을 쓰므로 `s3:GetObject`가 필요합니다.
- 인식 결과는 Transcribe가 관리하는 저장소에 두고 임시 URL로 읽기 때문에 **결과 쓰기 권한은 주지 않습니다**.

## 3. Lambda `practice-lambda`
| 항목 | 값 |
|---|---|
| 함수 이름 | `practice-lambda` |
| 런타임 | **Python 3.12** |
| ARM64 아키텍처 | 켜기 |
| 사용자 지정 실행 역할 | 켜기 → `role-practice-lambda` |
| 지속적인 실행, EC2 용량 공급자, 함수 URL, VPC | **모두 끔** |

생성 후:
1. 코드 탭 → `lambda_function.py`에 `lambdas/practice_lambda.py` 전체 붙여넣기 → **Deploy**
2. 구성 → 일반 구성 → 제한 시간 **0분 10초**
3. 구성 → 환경 변수 → `RECORD_BUCKET` = `local-speak-rec-2026`
4. 테스트 이벤트 (경로 검증 확인용, Transcribe 비용 없음):
   ```json
   {"requestContext": {"http": {"method": "GET"}}, "pathParameters": {"jobId": "abc"}}
   ```
   → `400` + "작업 ID가 올바르지 않습니다."가 나오면 코드 배포 성공. 실제 인식은 5단계 웹 화면에서 확인합니다.

## 4. API Gateway 경로 2개 + CORS
1. `local-speak-api` → **경로** → **생성** → `POST` `/practice` → 생성
2. 다시 **생성** → `GET` `/practice/{jobId}` → 생성
3. `/practice`의 **POST** 클릭 → **통합 연결** → 새 통합: Lambda → `practice-lambda` (페이로드 2.0)
4. `/practice/{jobId}`의 **GET** 클릭 → **통합 연결** → **기존 통합 선택**에서 방금 만든 `practice-lambda` 통합 선택
5. 왼쪽 **CORS** → **구성** → **Access-Control-Allow-Methods**에 **GET 추가** (POST, OPTIONS는 그대로) → 저장
   - 이걸 빠뜨리면 브라우저가 결과 확인(GET)을 막습니다.
6. 스로틀링(버스트 2, 요율 1)은 그대로 적용됩니다. 프론트는 3초 간격으로 결과를 확인해서 여기에 걸리지 않습니다.

## 5. 프론트 갱신 + 접속 주소
1. 웹사이트 버킷 `local-speak-web-2026` → **업로드** → 새 `frontend/index.html`로 덮어쓰기
2. **HTTPS 주소로 접속**: `https://local-speak-web-2026.s3.ap-northeast-2.amazonaws.com/index.html`
   - 브라우저는 보안 연결(HTTPS) 페이지에서만 마이크를 허용합니다. 기존 웹사이트 주소(`http://...s3-website...`)에서는 녹음 버튼이 안내 문구만 보여줍니다.
   - 같은 버킷·같은 파일이라 추가 리소스·비용 없음. CloudFront(사용자 지정 도메인 + HTTPS)는 가상 아키텍처로 표기.
