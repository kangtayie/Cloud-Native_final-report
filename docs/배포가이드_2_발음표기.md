# 2단계 배포 가이드: 발음 표기 (Amazon Bedrock)

리전은 1단계와 같은 **서울(ap-northeast-2)** 입니다. 번역 결과 아래에 **영어식 발음 + 한글 발음**을 붙입니다.

```
브라우저 → API Gateway POST /pronounce → pronounce-lambda → Amazon Bedrock (Converse API)
```

## 0. 모델 고르기 (Bedrock 콘솔, 서울 리전)
Bedrock은 **프리 티어가 없고 토큰 단위로 과금**됩니다. 저가 모델 후보 중에서 고릅니다.

1. 콘솔 → **Amazon Bedrock** → 왼쪽 **모델 카탈로그**
2. 아래 후보가 서울에서 쓸 수 있는지 확인합니다 (교차 리전 추론 프로필 `apac.`/`global.` 포함).
   | 후보 | 단가 (1M 토큰, 입력 / 출력) | 1회 호출 비용 (입력 약 250, 출력 약 150토큰) | 1,000회 |
   |---|---|---|---|
   | Amazon **Nova Lite** (서울) | $0.071 / $0.284 | 약 $0.00006 | 약 $0.06 |
   | Anthropic **Claude Haiku 5.5** (글로벌 교차 리전) | $0.10 / $0.50 | 약 $0.0001 | 약 $0.10 |
   | Amazon **Nova Pro** (서울) | $0.95 / $3.80 | 약 $0.0008 | 약 $0.81 |
   - 출처: AWS Price List API, 서울(ap-northeast-2) 온디맨드 표준 요금 (2026-11-16 조회).
   - 실제 확인 결과 (2026-11-16): Claude Haiku 5.5는 이 계정에서 `AccessDeniedException`(계정에 모델 미허용)으로 사용 불가.
   - 플레이그라운드 비교 (개선 프롬프트, 폴란드어 "Gdzie jest biuro administracji akademika?"):
     | 모델 | 한글 발음 결과 | 평가 |
     |---|---|---|
     | Nova Lite | 그제 예스트 뵤-로 앗-미-니-스뜨라-쯔이 … | 한글에 하이픈 금지 지시 무시, "뵤로·앗"처럼 부정확 |
     | Nova Pro | 그제 예스트 뷰로 아드미니스트라츠이 아카데미카 | 띄어쓰기·형식 준수, 실제 발음에 가까움 |
   - **결정: Nova Lite** (비용 최소 원칙, Nova Pro의 약 1/13). 한글의 하이픈은 람다에서 후처리로 제거하고, 남는 발음 오차는 화면의 "AI 참고용" 안내와 보고서 한계로 처리합니다.
3. 모델 카드에서 **플레이그라운드에서 열기**로 아래 프롬프트를 한 번씩 넣어 보고, **한글 발음이 더 자연스러운 모델**을 고릅니다.
   ```
   You write pronunciation guides for Korean speakers. Given a sentence in Polish, return ONLY a JSON object with "romanization" and "hangul".
   Gdzie jest biuro administracji akademika?
   ```
4. 고른 모델의 **모델 ID 또는 추론 프로필 ID**를 복사합니다 (예: `apac.…`, `global.…`로 시작하는 값). 5단계에서 씁니다.
   - Anthropic 모델은 처음 쓸 때 **사용 사례 양식**을 한 번 제출해야 할 수 있습니다.

## 1. IAM 역할 `role-pronounce-lambda`
1단계와 같은 방법(AWS 서비스 → Lambda → `AWSLambdaBasicExecutionRole`)으로 만들고, 인라인 정책 `bedrock-minimal`을 붙입니다.
확정 모델: **Nova Lite**, 추론 프로필 ID `apac.amazon.nova-lite-v1:0` (서울에서 호출 → 아시아 태평양 리전으로 분산).

```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Action": "bedrock:InvokeModel",
    "Resource": [
      "arn:aws:bedrock:ap-northeast-2:*:inference-profile/apac.amazon.nova-lite-v1:0",
      "arn:aws:bedrock:*::foundation-model/amazon.nova-lite-v1:0"
    ]
  }]
}
```
- 첫 줄: 서울에 있는 추론 프로필을 호출할 권한, 둘째 줄: 프로필이 요청을 보내는 각 리전의 Nova Lite 모델 권한 (둘 다 있어야 동작)
- **특정 모델만 호출 가능**하게 제한합니다 (PRD 5장 IAM 표). 다른 비싼 모델은 호출할 수 없습니다.
- 교차 리전 추론 프로필은 요청을 다른 리전으로 보낼 수 있어서 모델 줄의 리전 자리는 `*`로 둡니다.

## 2. Lambda `pronounce-lambda`
1단계와 같은 화면에서 만듭니다.
| 항목 | 값 |
|---|---|
| 함수 이름 | `pronounce-lambda` |
| 런타임 | **Python 3.12** |
| ARM64 아키텍처 | 켜기 |
| 사용자 지정 실행 역할 | 켜기 → `role-pronounce-lambda` |
| 지속적인 실행, EC2 용량 공급자, 함수 URL, VPC | **모두 끔** |

생성 후:
1. 코드 탭 → `lambda_function.py`에 `lambdas/pronounce_lambda.py` 전체 붙여넣기 → **Deploy**
2. 구성 → 일반 구성 → 제한 시간 **0분 15초** (LLM 응답이 수 초 걸릴 수 있음)
3. 구성 → **환경 변수** → 편집 → 추가
   | 키 | 값 |
   |---|---|
   | `MODEL_ID` | `apac.amazon.nova-lite-v1:0` |
   | `MAX_TOKENS` | `400` |
4. 테스트 이벤트:
   ```json
   {"requestContext": {"http": {"method": "POST"}}, "body": "{\"text\": \"Gdzie jest biuro administracji akademika?\", \"lang\": \"pl\"}"}
   ```
   → `200` + body에 `romanization`, `hangul`이 나오면 성공

## 3. API Gateway 경로 추가
1. API Gateway → `local-speak-api` → **경로** → **생성** → `POST` `/pronounce` → 생성
2. 만든 `POST`를 클릭 → **통합 연결** → 새 통합: **Lambda** → `pronounce-lambda` (페이로드 **2.0**)
3. 자동 배포가 켜져 있으므로 별도 배포는 필요 없습니다. CORS·스로틀링(버스트 2, 요율 1)은 스테이지 기본값이 그대로 적용됩니다.

## 4. 프론트 갱신
1. S3 버킷 `local-speak-web-2026` → **업로드** → 새 `frontend/index.html`로 덮어쓰기
2. 웹사이트에서 강력 새로고침(Ctrl+F5)

## 보고서용 캡처
- 람다 목록 (3개), API 경로 목록 (`/translate`, `/speak`, `/pronounce`)
- `role-pronounce-lambda` 인라인 정책 (특정 모델 ARN으로 제한) — **최소 권한 근거**
- 환경 변수 `MODEL_ID` 화면 — 코드 수정 없이 모델 교체 가능한 설계 근거
- 실제 화면 (번역 + 발음 표기 + 목소리)
- 콘솔 캡처(계정 ID가 보이는 화면)는 제출용 보고서에만 쓰고, 공개 레포(README)에는 서비스 UI 캡처만 올린다
